# 三维扫描与模型（试验版）

服务端另有可选的 [CPU 高精度工作进程](../tools/reconstruction/README.md)，包含主体分割、畸变标定与独立选择的轮廓外形模式。它不会替换手机 Vulkan 引擎；仍须按真实模型验收，不能把轮廓估计视为完整实测模型。

Android 1.3.7 的“工程拍摄 → 三维扫描”支持从系统相册选取照片、引导绕拍、手机本机生成，以及上传原片交给服务端生成。输出是包含空间顶点、法线、原照片贴图和三角面的 GLB 网格，可在手机和网页拖动旋转、缩放、自动环绕与复位；并非把照片按顺序播放的转台动画。

## 使用

1. 登录后新建扫描，输入物体／设备名称并选择有写入权限的云端目录。房间／现场入口处于试验阶段，先以小物体验证效果。
2. 从系统相册按拍摄顺序选择同一对象的照片，或进入引导相机。固定使用后置主摄和 1× 焦距；点取景对焦，保持物体、光照和拍摄方向稳定。照片不添加水印，避免同一位置的文字干扰匹配；工程水印相机的原有配置不受影响。
3. 带着手机绕静止物体走一圈，镜头始终对着物体，再略高、略低补拍。每移动约 10–15° 拍一张，建议 36–72 张，相邻画面重叠约 70%。步骤计数是建议，不代表传感器已经验证覆盖率。透明、镜面、纯色、移动物体以及只在原地转动手机，都可能导致重建失败。原地站立、只转动手机主要改变朝向，缺少恢复深度所需的视差，适合全景拍摄，不能代替环绕物体的三维采集。
4. 选择“手机本机生成”：深度模式自动优先 Vulkan，驱动不支持或计算失败时回退 CPU；也可明确指定 CPU 或 Vulkan。轮廓精细当前在 CPU 运行。明确指定 Vulkan 时不可用会报错，不会暗中把 CPU 标为 GPU。生成在前台服务中运行，通知栏可停止；快速／精细任务分别有 30／90 分钟上限。
5. 本机模型生成后可离线查看、分享 GLB 或加入持久上传队列。扫描原片与模型保留在应用私有目录，可手动“清理本机扫描”；卸载／清空应用数据会删除尚未保存或上传的扫描。
6. 选择“上传原片和视频 · 服务端生成”：原片进入已有续传队列，保存在选定目录下的“扫描名称-标识/原始照片”，该扫描保存的源视频同时进入“原始视频”。上传遵循 Wi-Fi、暂停及充电策略；全部上传完成后自动提交有幂等标识的服务端任务。选择精细质量、全部照片都来自同一个源视频且服务端支持高精度视频时，自动交由服务端 CPU 重新选帧；混合补拍照片等其他情况保留使用整组照片。模型保存到所选云端目录，可在文件页打开。中断准备原片后可继续提交。
7. 网页进入原片所在的文件夹，点击“三维扫描”，勾选 JPEG/PNG 原片后提交。任务有进度、取消、历史记录与模型下载／预览入口。文件列表中双击 `.glb` 同样可以查看，回收站也支持模型预览与下载。

### 视频环绕采集

选择“环绕录像 · 自动选帧”，点击快门开始，再次点击结束；固定后置主摄、1×、无声、无水印，最长 90 秒。辅助网格与中心标记只显示在取景中，不写进视频，也不是传感器水平仪或已验证的覆盖提示。请带着手机围绕静止物体慢走，始终让物体留在画面内，避免摇晃、快速转向与数字变焦。

也可“从视频自动选帧”导入 3 秒至 3 分钟、最大 512 MB 的连续视频。Android 8.1 起支持：快速／精细最多检查 240／600 个低分辨率候选画面，在覆盖整段视频的时间区间中选择较清晰者，再过滤曝光／纹理不足和近乎重复的画面；最多添加 48／96 张、最长边 3840 像素的 JPEG，遵循扫描的总照片与容量限制。它是启发式筛选，不能保证去掉所有模糊，也不能仅靠画面差异判断视差，最终仍由重建阶段验证几何。

源视频保留在该扫描的应用私有目录，可重新选帧；已经选取过的视频会拒绝重复加入同一扫描。选帧时保持应用打开；停止或解码失败不会留下半组照片，也不会修改已有原片。提交服务端时会上传源视频，单纯本机生成不会自动上传或写入系统相册。清理本机扫描／卸载会删除本机副本，请先确认上传完成。视频帧保留来源与帧时间说明，不伪造快门、ISO 等单张照片参数。视频存在压缩和运动模糊，光线充足时更方便；需要精细细节时仍建议原始照片。

目前手机和服务端单次最多 120 张，原片合计最多 512 MB；单张 JPEG/PNG 不超过 40 MB、8000 万像素和每边 16000 像素。相册其他图片格式由系统解码后转 JPEG。采集相机会补充可用焦距标定，导入照片优先读取 35mm 等效焦距 EXIF；缺少标定时使用估计值，混合镜头／变焦照片可能无法重建。

## 计算链路与当前边界

共享 C++ 引擎使用 OpenCV 做 SIFT、几何匹配、相机定位及空间点细化；多视角平面扫描深度计算有 CPU 和 Vulkan 两套实现，随后做一致性过滤、TSDF 深度融合及网格生成。无需 CUDA。手机和服务端使用同一套源代码，输出记录实际计算后端与已注册相机数量。

已经用同一组 48 张独立渲染的物体照片验证 Windows CPU、GTX 1050 Ti Vulkan 和 REDMI K80 Pro（Adreno 830）Vulkan；照片没有把真实相机位置传给引擎。真实透明矿泉水瓶绕拍测试已暴露明显缺面和碎片，未达到可用的完整物体重建质量；成功生成 GLB、注册全部相机及能旋转预览，只说明流程运行，不能作为模型质量验收。仍需对更多真实设备、现场和手机做质量及稳定性验证。1.3.2 起对可见三角面选择原照片并写入 UV／JPEG 贴图，少量无法投影的表面回退顶点颜色。贴图独立于深度图分辨率，不再把低分辨率颜色平均当成文字外观；尚无生产级纹理图集融合和测量标尺；已加入有计算量限制的联合束调整及独立视角支持的小缺口修补，相邻照片交界仍可能有接缝或重影。模型可能有孔洞或细节损失，不能直接作为尺寸测量或工程验收依据；房间／大场景尚未完成真实现场验收。

## 构建与安装运行库

Windows 构建机需要 CMake、Visual Studio C++ 工具链、Python 3；Android 还需要 NDK 29.0.14206865。脚本只在项目 `.test-data` 下载官方依赖，并校验固定 SHA-256；原生输出在 `artifacts/reconstruction-native`，不纳入 Git。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-reconstruction.ps1 -Runtime win-x64
powershell -ExecutionPolicy Bypass -File scripts/build-reconstruction.ps1 -Runtime android-arm64
powershell -ExecutionPolicy Bypass -File scripts/build-reconstruction.ps1 -Runtime android-x64
```

Android 发布会检查重建库、C++ 运行库、四个 Mono AOT 程序集与离线查看器是否实际装入 APK；本机库按 16 KB 页面对齐。未生成对应原生库时 Release 构建会失败。

将 `artifacts/reconstruction-native/win-x64` 的完整内容放进服务端程序目录的 `reconstruction` 子目录，随带 `Notices`。服务端从这里启动隔离的原生子进程；也可用 `MyPan__ReconstructionEngine` 指定可执行文件的绝对路径。运行库需要 Microsoft VC++ x64 运行时。缺少引擎时网页如实显示不可用，普通云盘功能可以继续使用。

Linux／macOS 可使用 CMake 及系统 OpenCV、Vulkan-Headers、glslang 构建同一 C++ 源码，但这次没有生成和验收它们的原生重建运行包；macOS GPU 需另做适配。iPhone 端尚未交付，不能把 Android Vulkan 支持等同于 iOS 支持。

## 权限、恢复与迁移

每个用户最多两个排队／运行任务，全局最多十六个，原生子进程单任务执行。原片读取与模型发布均检查当前账户、照片版本、文件夹权限及配额；客户端管理员不能跨用户读取私有原片。任务只对创建者列出，完成结果由普通文件权限控制。

服务端任务记录位于数据目录 `reconstruction/<任务标识>/job.json`，生成时使用受限临时目录，结束后清理原生计算输入和输出；云端原片和模型通过普通 CloudStore 保存。服务端重启会把中断任务标为失败，原片可重新提交。任务元数据纳入一键迁移备份；重建工具本身需随运行包单独迁移。任务提交、取消及后台生成结果进入审计记录。

模型查看器资源随程序离线部署，不使用外部 CDN；手机 WebView 仅允许本地查看器和指定模型，不开放 JavaScript 到原生桥接。服务端模型下载、回收站与版本检查沿用已有认证。完整许可证见 `THIRD-PARTY-NOTICES.md` 和各运行包 `Notices`。

## 文字细节与重新生成

快速预览使用最高 2K 原图贴图；精细模式使用最高 4K，并提高深度与融合分辨率。为控制手机内存，多张贴图合计解码像素分别限制在 64／128 Mi 像素，照片较多时自动降低单张纹理尺寸；不会把低分辨率原片放大来假装有细节。视频抽帧最长边提高至 3840，不超过源视频实际分辨率；应用内环绕录像优先采用相机支持的 1080p 预览输入及 12 Mbps H.264，实际能力受设备影响。

旧 GLB 不会自动变清晰。保留原片的本机扫描可选择生成质量，再点击“用原片重新生成 · 保留旧模型副本”；副本保存在扫描私有目录，失败或取消会恢复旧模型。成功后可重新选择上传新模型。网页可用同一组原片新建任务，旧云端模型保留。原片自身失焦、运动模糊、视频压缩、光照变化和相机定位误差仍会影响文字，近距离清晰照片通常更适合精细标签。

模型是自包含 GLB，内嵌用于贴图的照片图像；这些图像可以从模型中提取，可能包含拍摄背景。分享前应检查照片内容，云端权限仍沿用普通文件权限。

局域网 UI 验证可设置 `MYPAN_TEST_DIRECT_LAN=服务器内网IPv4`，脚本会让隔离服务监听全部 IPv4 网卡，并直接连接该 IP，不创建 ADB 转发。配合 `MYPAN_TEST_OFFLINE_EXIT=true` 可验证无响应服务器时的退出流程。此脚本仍仅允许模拟器。

## 手持与视频定位改进（1.3.4）

不要求相机始终水平或沿理想圆轨迹移动；模型估计每张照片的三维旋转和平移。采集仍须有相邻视角重叠、物体稳定且对焦清楚。普通倾斜、上下晃动和不规则步幅，与已经丢失细节的失焦／运动模糊是不同问题；算法不能保证恢复原片中不存在的文字细节。

- 特征分析提高到最长边 1024、最多 6000 个 SIFT 特征，采用 FLANN 搜索；合并轨迹时拒绝同一相机的冲突边，避免整条有效轨迹被冲突匹配丢弃。
- 在不同起始视角尝试初始化，未知焦距的照片尝试有限组初值；相机与空间点采用有 Huber 权重、阻尼和尺度约束的联合优化。最多优化 6000 点、每点 12 个观测；可取消。未定位照片会直接与已验证三维点的多视角描述子重新匹配，通过 PnP、重投影误差和画面分布检查后才计为已注册。最终仍要求至少 70% 原片完成定位，不用插值相机冒充成功。
- “物体／设备”利用多个相机中心视线估计居中物体范围，限制远处背景参与深度和体积融合；物体应留在画面中心区域。房间／现场保留全场景范围，通过原生 v2 接口传递模式；旧接口仍兼容。
- 深度估计按共视与几何基线选最多三个视角，以两个有效视角的相关性进行鲁棒匹配；先粗搜索，再用 5×5 窗口细化逆深度。CPU 与 Vulkan 使用相同流程，CPU 行计算使用受限 OpenCV 并行。模型依然只融合测得的表面，不把透明瓶身用假球壳补齐。
- 扫描相机默认对中心物体测光／对焦。应用内新录制视频保存实际镜头焦距及传感器裁切对应的等效焦距，抽帧时写入 EXIF；导入视频缺少标定时仍需估计。选帧按中心物体清晰度评分，避免清晰背景掩盖失焦物体；此筛选依然是启发式，不能保证所有帧可定位。

数值回归包含相机／空间点／焦距恢复、尺度约束、取消、已知平面的深度误差和真实 CPU／Vulkan 一致性。`tests/reconstruction-fixture.py --handheld --output 路径` 生成不规则轨迹、约 ±9° 滚转、起伏和偏心构图的独立合成照片，不向引擎提供相机位姿。真实罐装物与透明瓶实测另行检查，不能用合成通过替代真实质量验收。

数学方法参考：[Ceres 的束调整与 Schur 方法说明](https://ceres-solver.readthedocs.io/latest/nnls_tutorial.html#bundle-adjustment)、[OpenCV 相机姿态及三角化](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。当前实现为项目内有界求解器，没有新增 Ceres 运行库依赖。

## 本机精细与重新选帧（Android 1.3.7）

扫描详情可以直接选择本机“快速／精细”，均在手机运行，支持 Vulkan 与 CPU。精细采用 448 像素深度、128 个逆深度搜索层、最多 4 个共视邻居及 208³ 融合网格；快速保持 256 像素、64 层。精细融合使用经过往返投影校验的深度；只在局部平面成立且至少两个独立视角支持时修补小缺口，插值结果不能互相证明。贴图检查真实三角面朝向、顶点遮挡，并按表面积选择连续来源。精细任务上限 90 分钟，可停止；原片和旧模型保留。

“从原视频重新提取关键照片”对已完成的扫描同样可用。系统复制原视频及镜头标定到新的扫描版本，不混入旧帧，也不删除旧模型。精细最多检查 600 个候选、选 96 张；快速最多检查 240 个候选、选 48 张。少于目标数时不会复制帧凑数。选帧中断后原扫描不变，新版本可重试。

新增“轮廓精细”：手机本地 MobileSAM／ONNX Runtime 只识别主体轮廓，C++ 完成相机与焦距优化、192³ 轮廓交集、可靠支撑平面约束、原片投影贴图及全视角轮廓检查。无需上传或 CUDA，当前轮廓链路使用 CPU；“深度精细”仍支持 Vulkan。两种模式明确分开，轮廓模式不能恢复未拍到的内凹、内部结构和底部细节。原片像素不进行生成式补画。

本机轮廓与服务端采用同类几何流程，但相机标定和贴图实现不同，不保证相同质量。手机共享算法已在 Windows 用同一批 60 张未修改矿泉水原片验证；它不是在真实手机完成的性能验收。导出的本地识别模型与原始模型在三张真实照片上的二值掩膜完全一致。

构建机先运行 `powershell -File scripts/build-mobile-masks.ps1`（Python 3.13），再编译原生 Android 库与 APK。模型导出使用固定版本和校验值，模型文件约 44.5 MB，随 APK 离线打包；导出工具含 PyTorch，手机只运行 ONNX Runtime CPU。构建脚本与应用均验证模型 SHA-256，APK 包含 MobileSAM 许可。`tests/reconstruction-mobile-masks.py` 比较导出模型与固定原模型；`tests/MyPan.ForegroundTests` 调用实际 Android 共用 C# 分割和 C++ 重建；几何回归验证已知球体、闭合拓扑、遮挡与取消。

轮廓模式缺失超过 120° 环绕方向、轮廓重投影中位 IoU 小于 0.90 或第 10 百分位小于 0.85 时不发布模型。这些是失败检测，不是测量精度。旧模型会在新一轮生成失败时恢复。重新选帧保留所选精细模式；提交云端时明确映射为服务器轮廓模式（quality=3），不静默替换为深度模式。

## 服务端可复现的重建模式

网页默认选择精细设备／实物（quality=2）。矿泉水瓶等透明物体应明确选择“透明瓶身／光滑物体 · 轮廓外形重建”（quality=3），以运行完整的相机标定、轮廓交集、支撑平面约束和原片贴图。quality=0/1 是 C++ 草稿／本机算法对照，不应拿它们的输出与轮廓模型视为同一个流程。任务记录显示实际模式；高精度工作进程不可用时不再静默降级到对照引擎。

高精度 worker 完全由程序从提交的原片生成，使用本地 MobileSAM vit_t 产生前景掩膜、COLMAP 标定以及几何和贴图算法。没有调用生成式图片服务补画或替换原片。JPEG 直接复制保留原始像素与 EXIF。质量报告记录模式、算法源码哈希、输入照片 SHA-256、相机覆盖和轮廓指标，可由任务所有者下载；指标用于发现失败，不是几何精度证明。轮廓法生成外形近似，不能恢复未观察到的内凹和内部结构。

## 全景看房预览

宽高比 2:1、命名为 `名称.360.jpg`／`.360.png` 的等距柱状全景图，在网页双击后可拖动环视、滚轮／双指缩放和全屏查看。查看器离线随服务端部署，图片仍需经过原有权限和版本检查。全景拼接不等于可自由移动的三维房屋网格；视频未覆盖的顶部和地面显示深色区域。

新增验证：`dotnet run --project tests/MyPan.ScanTests -c Release` 检查完成扫描的重新选帧版本隔离、原片／旧模型保存、取消与路径边界；原生几何测试检查独立视角支持的小缺口恢复及真实开口保护。
