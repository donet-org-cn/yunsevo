# 多文件与大文件同步

## 已实现

- 文件清单和云端文件夹选择在单次请求内建立权限、目录和组成员索引，复用同一不可变目录快照，避免为每个文件重复遍历所有目录与权限规则。索引不跨账号或版本缓存，权限修改仍使 ETag 失效；其他用户的个人目录和只共享后代的结构性祖先保持原有可见性。
- 原子状态和增量日志写入在事务边界执行 `Flush(true)`，避免在每次缓冲写入时再额外启用 WriteThrough。仍然先确认数据落盘，再发布状态或返回成功；保留原子替换、断尾恢复及代际校验。

- 文件传输按最多 64 个独立文件组织一批，默认同时传输 4 个文件。多个任务的上传共享并发上限，完整副本下载也共享上限，避免任务数量直接放大网络与缓冲区占用。目录创建、重命名及删除仍按依赖和原有安全规则处理。
- 目录请求限定到任务的云端范围，使用包含账户及权限上下文的 ETag。无变更返回 304，不重复传输完整清单；账户、用户组及权限变化会使缓存失效。仍保留文件监听、服务端推送和补查机制。
- 客户端以带校验值的增量记录保存已完成文件，上传批次合并落盘，定期合并完整状态。无变化的同步周期不重写完整客户端状态。中断尾记录可以丢弃，完整记录校验失败会停止恢复，不能静默重置状态。
- 服务端文件提交先持久化 `catalog.journal`，再发布新目录和变更通知。每 128 条文件提交或发生账户、权限等元数据事务时合并目录快照。日志与快照使用代际标识，避免中断后的旧日志覆盖新快照。

## 大文件

新版服务端与客户端之间，至少 16 MiB 的上传使用 8 MiB 分块。确认的上传偏移在服务端持久化，客户端保存会话记录；网络断开、客户端重启或服务端重启后，从服务端确认的块边界继续。传输中断的一块需要重新发送。

每块及完整文件均校验 SHA-256。完整校验通过、版本条件仍然成立、容量配额允许时才提交文件，未完成的上传不会出现在云端文件列表。提交重试返回同一版本；同步引擎可以恢复已提交但本地尚未记录的上传回执，避免把这类文件误判为双端冲突。

文件源在传输时保持打开，并保留原有写入保护；复用断点前会重新核验源内容。校验会产生额外磁盘读取，这是恢复正确性的成本，并非零拷贝或块级去重。旧服务端未声明续传能力时，新客户端继续使用流式 PUT。

完整副本下载按文件 ID、版本保留部分数据，以 HTTP Range 续传；使用与本地目标同一父目录下的独立暂存目录，成功后原子替换目标。若无权创建暂存目录或目标位于不同文件系统，退回目标目录内的单次下载，保持替换的原子性。下载结束前会再次检查本地修改并保留冲突副本。暂存目录名称为 `.yunsevo-transfers-<标识>`，不在同步根目录内部，不参与上传。

Windows 按需下载共享受控的水合并发，以最多 8 MiB 的 HTTP 范围请求读取，按 1 MiB 向 Windows 提交已到达的数据。临时网络错误从尚未提交的数据位置重试；版本变化时停止，避免拼接不同版本。

## 设置

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 客户端环境变量 `YUNSEVO_TRANSFER_CONCURRENCY` | 4 | 并发文件数，允许 1–8；机械硬盘或弱服务器可调为 1–2。 |
| 服务端 `Yunsevo__MaxUploadBytes` | 20 GiB | 单文件上限，普通与分块上传均受此限制。 |
| 服务端 `Yunsevo__MaxPendingUploadBytes` | 40 GiB | 未完成分块上传的声明大小总预留上限；不是预分配磁盘空间。 |
| 服务端活动上传会话 | 每用户 8 个、全局 128 个 | 限制未完成的分块上传数量。 |
| 服务端分块数据并发 | 8 | 同时读写的分块请求数。 |

分块会话每成功接收一块续期至 24 小时；过期暂存数据在后续创建会话时清理，完成回执同样保留至过期。已提交文件仍受现有配额、版本保留、回收站和权限约束，提交时再次检查，不能用并发分块绕过配额。

断点偏移使用两个独立校验的固定进度槽交替落盘，数据先持久化，再确认进度；槽记录中断时可退回上一份有效记录并重传最后一块，避免每块完整替换 JSON 元数据。

Windows 按需上传的恢复记录位于 `%LOCALAPPDATA%/YunsevoTransfers`；完整副本客户端使用状态文件旁的 `.transfers` 目录。记录不保存密码或访问令牌。完整副本下载暂存会保留，便于稍后续传；不再需要的暂存文件可在相关任务停止后清理。

## 备份与性能边界

网页迁移备份从一致的已提交快照生成完整目录，包含日志里已提交的数据，不包含未完成上传。直接复制数据目录时必须先停止服务，并完整保留 `catalog.json`、`catalog.journal`、`blobs`、密钥和其他配置；不能只复制目录快照，也不能直接用不识别增量日志的旧程序回退。客户端备份也应连同状态文件旁的 `.journal` 保存。

目前目录仍以内存快照和文件日志存储。这次优化减少重复扫描、整表传输和写盘次数，没有改成数据库，也没有实现差分块去重。百万级目录、超多并发用户或高可用部署仍需要专门的容量测试及数据库/对象存储改造。

复测工具：

```powershell
dotnet run --project tests/Yunsevo.PerformanceTests -c Release -- --server=F:\yunsevo\artifacts\v2-update\server\Yunsevo.Server.exe --headless=F:\yunsevo\artifacts\v2-update\headless\Yunsevo.Headless.exe --label=native --files=300 --large-mib=64
```

所有测试数据在独立 `.test-data/performance-*` 目录。基准记录时间、字节校验、同步轮次和服务端峰值工作集；Native headless 模式包含进程启动与登录时间。回环网络、磁盘及杀毒扫描会影响结果，不代表公网吞吐。最终实测值与证据见发布目录的 `verification.json`。

本机 Windows AOT 的一次顺序对照（300 个 1 KiB 文件；旧版与最终新版分别启动，未并行运行其他回归测试）：

| 场景 | 旧版 | 新版 |
| --- | ---: | ---: |
| 小文件上传 | 45.90 秒，3 个同步周期 | 18.75 秒，1 个同步周期 |
| 小文件下载 | 21.15 秒 | 20.31 秒 |
| 64 MiB 连续上传 | 1.70 秒 | 2.46 秒 |
| 64 MiB 连续下载 | 1.31 秒 | 1.35 秒 |
| 服务端峰值工作集 | 约 33.2 MiB | 约 57.0 MiB |

这次小文件上传耗时降低约 59%，下载差异较小。大文件无故障连续上传增加了校验和持久化确认开销；主要收益是中断时不必整文件重传。没有宣称所有大文件上传都更快，也没有通过降低持久化保证换取表面吞吐。分块缓冲区与并发数受控，但进程工作集仍包含目录、连接池及框架开销。

原始数据：`.test-data/performance-native-baseline-20261018031226/benchmark.json`、`.test-data/performance-native-final-20261018031941/benchmark.json`；汇总见 `.test-data/v25-performance-comparison.json`。64 MiB 验证不等同于已经完成 20 GiB 或公网压力测试。

## 初始化与权限索引优化对照

本轮与上一已安装版本做顺序运行的本机 Windows Native AOT 对照；文件传输每个版本各一次，包括无界面客户端启动和登录。

| 场景 | 优化前 | 本轮 |
| --- | ---: | ---: |
| 300 × 1 KiB 上传 | 17.34 秒 | 15.84 秒 |
| 300 × 1 KiB 下载 | 17.44 秒 | 18.60 秒 |
| 64 MiB 连续上传 | 2.68 秒 | 2.56 秒 |
| 64 MiB 连续下载 | 1.29 秒 | 1.47 秒 |

小文件上传在这组样本中降低约 8.6%；下载本次未提升，不能据此宣称整体吞吐都变快。未通过跳过校验、落盘确认或离线删除保护提速。

另用 3000 个合成文件元数据和约 100 条文件夹权限规则，比较普通设备用户的清单响应。每个版本预热后各测三次：目录响应中位耗时从 171.61 ms 降到 6.33 ms，文件夹选择从 7.35 ms 降到 1.08 ms；可见路径及权限的摘要完全一致。这里测量元数据响应，不包含文件内容传输，不代表公网带宽或真实多用户容量。

原始对照与二进制 SHA-256 见 `.test-data/v26-performance-comparison.json`；目录样本见 `.test-data/catalog-performance-2026-10-18T03-55-30-995Z/comparison.json`。首次安装与重启恢复说明见[首次安装](first-install.md)。
